# Contributing Guidelines

Thank you for contributing to this AI, LLM, AI Agents, and AIOps knowledge repository.

The goal is to maintain practical, accurate, well-organized learning materials focused on real-world engineering applications.

## 📁 Directory Organization

- Use numbered directories to maintain the learning sequence.
- Keep topics separated into logical categories.
- Use descriptive filenames.
- Avoid duplicate documentation.

Example:

```text
03-ai-agents/
├── ai-agents-fundamentals.md
├── agent-architecture.md
├── tool-calling-and-function-calling.md
└── guardrails-and-safety.md
```

## 📝 Documentation Guidelines

Each Markdown document should preferably contain:

1. Overview
2. Core concepts
3. Architecture or workflow
4. Key components
5. DevOps use cases
6. Practical examples
7. Commands or code samples
8. Security considerations
9. Best practices
10. Hands-on lab
11. References

## 💻 Code and Commands

- Use code blocks with the correct language.
- Include prerequisites before commands.
- Explain important commands.
- Avoid hardcoded credentials, API keys, tokens, and secrets.
- Use environment variables for sensitive information.
- Verify commands before documenting them.

## 🔐 Security Guidelines

- Never commit secrets or credentials.
- Do not execute AI-generated commands blindly.
- Use least-privilege permissions.
- Validate AI-generated infrastructure changes.
- Require approval for production modifications.
- Include security considerations in AI agent examples.

## 🤖 AI Agent Documentation

When documenting AI agents, explain:

- Agent goal
- LLM/model used
- Tools available
- Input and output
- Workflow
- Permissions
- Guardrails
- Failure handling
- Human approval requirements

## 📌 Pull Requests

Contributions should:

- Have a clear purpose.
- Follow the repository structure.
- Avoid unnecessary duplication.
- Include tested commands and examples when applicable.
- Update the roadmap if a new learning topic is added.

## 📖 Writing Style

- Use clear and technical language.
- Prefer practical examples over unnecessary theory.
- Include diagrams where they improve understanding.
- Keep content easy to navigate.
- Use consistent Markdown formatting.

## ⚠️ Disclaimer

AI-generated commands, scripts, code, and recommendations must be reviewed and tested before use, particularly when interacting with cloud environments or production systems.

Thank you for helping improve this repository!
